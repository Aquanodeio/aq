CLAUDE.md::1. **`$HOME` does not control where OpenSSH looks for `~/.ssh/config` — it resolves `~` from the passwd entry, not the environment.** Verified empirically (ticket #422): `HOME=/tmp/x ssh -G host` still read `/Users/<real-user>/.ssh/config`. This means you **cannot** sandbox an ssh-config-writing test by pointing `$HOME` at a scratch directory — `ssh`/`scp`/`aq ssh` will still touch the operator's real `~/.ssh`. To validate anything that writes ssh config or execs real `ssh`, either (a) back up the operator's real `~/.ssh` byte-for-byte first and restore it after, or (b) pass an explicit `-F <config>` / `IdentityFile` override on every invocation instead of relying on environment isolation. Also implies: any managed directive `aq` writes (e.g. `IdentityFile`) must use **absolute paths**, never a `~`-relative one — a tilde resolves against the same passwd-derived home inside a container/CI job where `$HOME` may differ from where the file actually lives.
CLAUDE.md::4. **SSH endpoint resolution must prefer `service_urls[].find(port === 22)`, falling back to `app_url` only when no such entry exists** — see `mjolnir/CLAUDE.md`'s SimplePod section for why trusting `app_url` alone is wrong (it can silently be the Ogre HTTP port, or `null` on Akash). See also `aquanode-backend/CLAUDE.md` gotcha #30: the `/deployments` list endpoint returns raw snake_case rows (no camelCase transform), unlike `/:id`/`/:id/status` — any Go struct decoding the list endpoint must use snake_case tags only.
