# aq — Aquanode CLI

Go CLI (`login|up|deploy|status|ssh|down|logout|whoami|version|help`). No external deps in `go.mod` — keep it that way unless there's no other way (e.g. prefer shelling out to `ssh-keygen` over pulling in `x/crypto` for key generation).

## Critical gotchas

1. **`$HOME` does not control where OpenSSH looks for `~/.ssh/config` — it resolves `~` from the passwd entry, not the environment.** Verified empirically: `HOME=/tmp/x ssh -G host` still read `/Users/<real-user>/.ssh/config`. This means you **cannot** sandbox an ssh-config-writing test by pointing `$HOME` at a scratch directory — `ssh`/`scp`/`aq ssh` will still touch the operator's real `~/.ssh`. To validate anything that writes ssh config or execs real `ssh`, either (a) back up the operator's real `~/.ssh` byte-for-byte first and restore it after, or (b) pass an explicit `-F <config>` / `IdentityFile` override on every invocation instead of relying on environment isolation. Also implies: any managed directive `aq` writes (e.g. `IdentityFile`) must use **absolute paths**, never a `~`-relative one — a tilde resolves against the same passwd-derived home inside a container/CI job where `$HOME` may differ from where the file actually lives.

2. **The managed `~/.ssh/config` integration writes an `Include` line near the TOP of the user's config, pointing at a separate `aq`-owned file — it never appends `Host` stanzas at EOF.** `ssh_config` is first-match-wins *per keyword*. Appending our `Host aq-*` block at the end of a user's config means any earlier `Host *` block (corporate `ProxyJump`, a 1Password/Secretive signing agent — both common) silently wins over our `IdentityFile`/`User`, and there's no error anywhere telling you why the alias didn't authenticate. `aq` therefore owns `~/.ssh/aquanode.config` outright (one block per active deployment, rewritten idempotently, pruned on `aq down`) and inserts exactly one `Include ~/.ssh/aquanode.config` line inside `# BEGIN aquanode` / `# END aquanode` markers, near the top of the real config so it's evaluated before conflicting blocks. Content outside the markers must stay byte-identical; damaged/foreign-looking markers should be refused rather than guessed at, and writes go through a same-directory temp file + rename (a half-written `~/.ssh/config` locks the user out of every host, not just aq's).

3. **No SSH host key is available anywhere in the platform — not in the platform's database schema, not on any API response.** `aq ssh` uses a dedicated `~/.ssh/aquanode_known_hosts` file with `StrictHostKeyChecking accept-new` (matching the platform's own internal posture) rather than the user's real `known_hosts` — GPU providers recycle IPs aggressively, and a recycled address colliding with the user's own infrastructure in their real `known_hosts` would eventually throw the full-screen "REMOTE HOST IDENTIFICATION HAS CHANGED" banner against something they actually care about.

4. **SSH endpoint resolution must prefer `service_urls[].find(port === 22)`, falling back to `app_url` only when no such entry exists** — trusting `app_url` alone is wrong: on some providers it is silently the on-box agent's HTTP port, and on Akash it can be `null`. Related decoding gotcha: the `/deployments` list endpoint returns raw snake_case rows (no camelCase transform), unlike `/:id` and `/:id/status` — any Go struct decoding the list endpoint must use snake_case tags only.

5. **`aq push` must assume neither `rsync` on the box nor GNU `tar` semantics on the laptop.** Three empirically-confirmed traps, all found on a real simplepod box: (a) the Docker-pool base image has **no `rsync`** — `probeRemoteRsync` asks the box before choosing, and the tar-over-ssh fallback is the path most providers actually take, so it is the one to test first, not the edge case; (b) recent macOS ships **openrsync**, not GNU rsync, and GNU-only flags (`--info=stats1`, `--info=progress2`) make it exit with a usage dump instead of transferring — every rsync flag `aq` emits must exist in both implementations (`-az`, `--stats`, `--delete`, `--exclude`, `--rsync-path` do); (c) macOS `bsdtar` archives resource forks and xattrs by default, so without `COPYFILE_DISABLE=1` **and** `--no-xattrs` every pushed file lands with an AppleDouble `._name` sibling in the user's `/workspace` and GNU tar on the box prints an "unknown extended header keyword" warning per file — the transfer succeeds, so this is invisible to an exit-code check and only shows up in the remote tree. `--no-xattrs` is itself probed before use, since it is not universal and an unrecognized flag would fail the push outright.

6. **`AQ_API_URL` used to be outranked by the stored credential, which made every "point aq at a local stack" validation a lie.** `aq login` persists the URL it paired against into `~/.config/aq`, and `newControlClient` read `cred.APIURL` first, falling back to the env var only when that was empty — which it never is for a logged-in user. Setting `AQ_API_URL=http://localhost:11080/api/v1` therefore did nothing, silently: the command printed a plausible deployment id and **rented a real billable box in production** while the operator believed they were exercising an unmerged branch. It cost two leaked prod deployments to notice. `resolveAPIURL` now puts the env var first (`down.go`), and `TestResolveAPIURLLetsTheEnvOverrideWin` pins it. The general rule this is an instance of: **an explicit environment override must outrank anything persisted**, and when validating an unmerged backend change, prove which host you actually hit — point at a capture server first and read the request — before trusting any result.

7. **`--gpus N` is an allocation request, not a guarantee of what the provider hands over.** Verified on simplepod: `--gpus 2` correctly persists `gpu_count=2` and scales cpu/memory/storage exactly 2x (deployment 3372: 22 cores / 28Gi / 457Gi vs 3369's 11 / 14Gi / 229Gi), and the billed rate is **identical** — because simplepod is a whole-node provider and hands over the entire physical box (3x RTX3070) either way. So on whole-node providers the flag does not change the hardware, it stops you from paying node price while configuring one GPU's worth. On providers that honour a count (runpod bakes it into the offer address, hyperstack passes it separately) it selects a different box. Never describe the flag as "rent N GPUs" — it is "ask for N GPUs' worth", and `MAX_GPU_COUNT = 8` in the orchestrator is the only ceiling that exists anywhere.


8. **The marketplace feed (`GET /api/v1/marketplace`, public/unauthenticated — the one endpoint `aq gpus` uses) types its per-GPU resource fields as numbers, not integers, and its `price` is the WHOLE offer's hourly rate.** `storagePerGpu`, `cpuCoresPerGpu` and `ramPerGpu` are node resources divided by GPU count, so whole-node providers routinely emit fractions (`2403.5`) — decoding them as Go `int` fails outright with `cannot unmarshal number 2403.5`, on real data, on the first run against prod. They must be `float64`. On `price`: of 142 comparable provider+model+region groups in a live snapshot, 139 scale exactly with `gpuCount`, confirming it is the offer total rather than a per-GPU rate — so any UI showing it must show `gpuCount` beside it or the number reads as per-GPU. The 3 that do not scale (akash listing 1xH100 and 2xH100 at an identical `2.7090`, one vastai row) are upstream feed quirks, not a decode error; do not "fix" them client-side. Related: this endpoint needs no credential, and the command built on it must never call `config.Load()` — depending on `~/.config/aq` parsing cleanly would reintroduce the login gate it exists to avoid.
